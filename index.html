Portfolio study / 001
Synthetic data · Demonstration

From drainage context
to a clear review.

An illustrative GIS case study connecting water resources, infrastructure, and data quality. All maps and records below were created for this portfolio; they do not represent a client project or real location.

The review question

How can a reviewer organize drainage context, locate infrastructure, and make data gaps visible before starting analysis?

Workflow demonstrated

Separate context from assumptions, present consistent map views, and turn a small set of data checks into traceable findings.

What this delivers

Three conceptual map plates and an interactive QA example. No hydrologic model, flow estimates, or engineering design conclusions are produced.

Map gallery

One setting. Three perspectives.

Original synthetic illustrations · Not georeferenced · Not to scale. Labels and symbols remain consistent across the gallery.

QGIS workflow concept · Interactive browser demonstration

Find the issue. Explain the next step.

This JavaScript demo checks four fictional line records for missing asset IDs, repeated IDs, and identical start/end coordinates. It illustrates a possible plugin workflow; it does not run QGIS or validate full geometry.

Coordinates use an arbitrary local grid with no CRS or units. They are unsuitable for measurement or real-world analysis. No uploads or data storage.

Enable JavaScript to run this sample.

    A result with no findings means only that these three checks found no issues. CRS suitability, connectivity, topology, slopes, capacity, and field conditions still require separate review.

    Methods, limitations, and next development step

    Method: Read each record, check whether its asset ID is blank, group repeated IDs, and compare the two endpoints. Findings identify the affected records and a follow-up action.

    Result: The flagged sample contains one missing ID, a repeated ID shared by two records, and one zero-length line. The corrected sample resolves these deliberately seeded issues.

    Next step: Implement and test the workflow privately in desktop QGIS against synthetic layers, including provider behavior, feature selection, and report export. The browser demonstration is not an installable plugin.

    Scope: These original illustrations and test records contain no client data. The study shows a review approach, not a completed drainage design or flood study.
